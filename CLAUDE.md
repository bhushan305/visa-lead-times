## How to ship a change
1. Edit code here; `npm run dev` → http://localhost:3010
2. `git commit` and `git push origin main`
3. Vercel auto-builds and promotes to production (~1–2 min). Pushes to other branches create preview deployments only.

No Vercel CLI link is needed. Don't change DNS at GoDaddy unless moving hosts.

## Data pipeline
1. **Scrape (daily, on the Mac):** Claude scheduled task "USCIS daily scrape" opens https://egov.uscis.gov/processing-times in Chrome and injects `scripts/uscis-scrape.browser.js`. It reads the tracked cases from the sheet's Config tab, calls USCIS's `getProcessingTime` server action for each, and POSTs the results to the Apps Script web app (`doPost` → Raw_Snapshots, Latest, Changes, Run_Log). It has to run in a real browser: USCIS returns 403 to curl, GitHub Actions and cloud IPs. If Chrome isn't running when the task fires, that day is skipped.
2. Google Sheet "USCIS Processing Times Tracker" `1CNcuKdmNqfSXtFfpiHZi3_bnnvurgqw8573JEBgStuI` (owner bhushan@marketcrunch.ai). Its bound Apps Script project serves `doPost` (scrape ingest, feedback emails) and `doGet` JSON (`?tab=latest|raw|changes|run_log|config|forms`) at `APPS_SCRIPT_URL`.
3. **Sync:** GitHub Action `.github/workflows/sync.yml` (daily, ~17:30 UTC, often runs later) runs `scripts/sync-sheet-to-supabase.ts`, then **fails if the last scrape is more than 50h old**, so GitHub emails an alert. Vercel cron `/api/cron/sync` (17:00 UTC) also exists.
4. `src/lib/data/repo.server.ts` reads Supabase first, then falls back to the live Apps Script API.
5. Historic FY averages: `data/historic-pt-seed.json` + `npm run seed:historic` (manual).

Manual run: open the USCIS page in Chrome, paste `scripts/uscis-scrape.browser.js` into DevTools, then poll `window.__uscis` until `phase` is `done`. Manual sync from this Mac: `npx tsx --env-file=.env.local scripts/sync-sheet-to-supabase.ts`.
Label gotcha: the sync keys forms by `form_label_selected`, so the scraper builds it as `<config form_code> | <title>` (e.g. `I-526(L) | ...`). Two labels for one form code break the forms upsert.

## SEO conventions
- Canonical tags go in `head().links` (not `meta`) via `canonicalUrl()` from `src/lib/site.ts`. A `{rel:"canonical"}` inside `meta` renders as `<meta rel=canonical>`, which Google ignores.
- `public/sitemap.xml` is generated at build time by `scripts/generate-sitemap.ts` (prebuild) and is gitignored. Without Supabase env vars it writes only the 16 static URLs.
- `public/robots.txt` and `public/ads.txt` are static files.

## Gotchas
- `src/routeTree.gen.ts` is auto-generated by the TanStack router plugin on dev/build. Commit it when it changes.
- `npx tsc --noEmit` reports ~23 pre-existing errors, mostly typed `<Link to="/form/i-485">` that should use `to="/form/$code" params={{code}}`. Vite builds don't type-check, so deploys still succeed.
- The project was originally built on Windows (`C:\Claude\VisaLeadTime`). On 2026-10-17 this Mac copy's `.git` was empty, so it was re-synced from GitHub (no history lost).
